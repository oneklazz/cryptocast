# Архитектура проекта

## Общая структура

Проект разделён на два слоя:

- **packages/core/** — переиспользуемая библиотека прогнозирования. Не зависит от
  FastAPI, Redis или любых других внешних сервисов. Можно установить
  отдельно через pip и использовать в любом другом приложении.

- **app/** — тонкий слой FastAPI. Принимает HTTP-запрос, вызывает core,
  возвращает результат. Управляет кэшированием через Redis.

## Компоненты

```
User → app/main.py → core/forecast.py → dataset/coin_*.csv
                  ↘ redis (кэш)
```

### Core

Единственная публичная функция: `make_forecast(csv_path, days) → dict`

Отвечает за: загрузку CSV, обучение модели Prophet, возврат прогноза.
Не знает ничего про HTTP, Redis или конфигурацию окружения.

### App

FastAPI-сервис с эндпоинтом `POST /predict`.
Принимает `coin` и `days`, формирует путь к CSV, вызывает `make_forecast`.
Подключается к Redis для кэширования результатов.

### Redis

Кэширует результаты прогнозов чтобы не пересчитывать одинаковые запросы.
Запускается как отдельный контейнер в docker-compose.

### Dataset

CSV-файлы с историческими ценами криптовалют.
Колонки: Date, Open, High, Low, Close, Volume, Marketcap.

## Граница между app и core

app знает про core, но core не знает про app.
Это означает: можно заменить FastAPI на CLI или Telegram-бота,
и core переписывать не придётся.

## Воспроизводимость

Приложение запускается в Docker-контейнере.
Redis запускается рядом через docker-compose.
Все зависимости зафиксированы в requirements.txt и core/pyproject.toml.
